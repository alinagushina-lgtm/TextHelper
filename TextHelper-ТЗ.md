# TextHelper для Windows — техническое задание

Домашнее задание: локальный помощник для обработки текста, работающий через иконку в системном трее и Claude Code в headless-режиме.

**Платформа:** Windows 11
**Дата:** 13 августа 2026

---

## 1. Концепция

Маленькое приложение, которое живёт иконкой в системном трее Windows. Пользователь копирует любой текст, кликает по иконке, выбирает действие — и получает результат в окне «БЫЛО → СТАЛО» с возможностью доработки.

Оригинальная схема задания сделана под macOS (иконка в menu bar, `Cmd+C`). Здесь она перенесена на Windows: системный трей рядом с часами, `Ctrl+C`, никаких обращений к AppleScript.

Ключевое ограничение: **API не используется**. Никаких HTTP-запросов к Anthropic, никакого `ANTHROPIC_API_KEY`. Приложение вызывает установленный локально Claude Code в headless-режиме, авторизация идёт через подписку пользователя.

---

## 2. Пользовательский сценарий

1. **Выделяет текст** в любой программе — в Word, браузере, почте. Нажимать `Ctrl+C` не нужно: приложение скопирует выделенное само.
2. **Жмёт кнопку на панели**, которая висит поверх всех окон, либо кликает по иконке ✦ в трее.
3. **Выбирает действие** — на панели или в выпадающем меню:
   - ✏️ Проверь орфографию
   - 🌍 Переведи на английский
   - 🎩 Сделай формальнее
   - 🔄 Упрости текст
   - — — —
   - ⚙️ Настройки
   - ❌ Выход
4. **Claude обрабатывает текст** — иконка меняется на ⏳, видно, что идёт работа.
5. **Появляется окно с результатом**:
   - поле «БЫЛО» — исходный текст (только для чтения)
   - поле «СТАЛО» — результат
   - поле ввода уточнения — «сделай ещё короче»
   - кнопка «Отправить» — запускает доработку
   - кнопка «📋 Скопировать» — кладёт результат в буфер обмена

**Что можно сделать дальше:**
- скопировать результат и вставить куда нужно;
- попросить доработать («сделай короче», «добавь деталей») — цикл возвращается к шагу 4;
- закрыть окно и начать заново с новым текстом.

## 3. Технические решения

| Вопрос | Решение | Почему |
|---|---|---|
| Язык | Python 3.14 (уже установлен) | Минимум кода, быстрый старт |
| Иконка в трее | `pystray` | Стандартное решение для трея на Windows |
| Окно | `tkinter` (встроен в Python) | Не тянет лишних зависимостей |
| Буфер обмена | `pyperclip` | Простое и надёжное чтение/запись |
| Картинка иконки | `pillow` (нужен для `pystray`) | Требование библиотеки |
| Связь с Claude | Запуск процесса `claude -p` | Работает через подписку, без API-ключа |
| Модель | Настраивается, по умолчанию `sonnet` | Для орфографии и перевода хватает с запасом, отвечает быстрее и экономит лимиты подписки |
| Распознавание речи | `sherpa-onnx` + модель Zipformer2 | Работает на компьютере, без интернета и без настроек Windows |

**Зависимости:** `pystray`, `pillow`, `pyperclip` — для трея, окон и буфера обмена. Для голосового ввода добавляются `sherpa-onnx`, `sounddevice`, `numpy`.

**Запуск:** одна команда — `python texthelper.py`

## 4. Как приложение обращается к Claude

Приложение запускает дочерний процесс:

```
claude -p --model sonnet
```

Текст промпта передаётся процессу через **стандартный ввод** (stdin), а не аргументом командной строки. Так безопаснее: в тексте пользователя могут быть кавычки, переводы строк и спецсимволы, которые ломают экранирование в Windows, плюс аргумент командной строки ограничен по длине.

**Обязательные детали реализации под Windows:**

- Кодировка процесса — UTF-8 (`encoding="utf-8"`, `errors="replace"`), иначе кириллица превращается в мусор.
- Флаг `CREATE_NO_WINDOW` — иначе при каждом вызове на экране мигает чёрное окно консоли.
- Рабочая директория процесса — отдельная временная папка, а не папка проекта. Иначе Claude Code подхватит `CLAUDE.md` и настройки чужого проекта и начнёт вести себя непредсказуемо.
- Таймаут 60 секунд. Не ответил — показываем ошибку и возвращаем иконку в исходное состояние.
- Вызов выполняется в отдельном потоке, интерфейс не замирает. Обновление окна — только из главного потока (через `root.after`).

### Структура промпта

Каждый запрос собирается из трёх частей:

```
Ты — помощник по обработке текста. Верни ТОЛЬКО готовый текст
без пояснений, без комментариев и без markdown-разметки.

Задача: <промпт выбранного действия>

=== ТЕКСТ ===
<текст пользователя>
=== КОНЕЦ ТЕКСТА ===
```

Строгая инструкция «верни только текст» обязательна: без неё Claude отвечает в разговорном стиле («Вот исправленный вариант: …»), и это попадает в поле «СТАЛО».

### Доработка — самое важное место

Каждый вызов `claude -p` — **отдельный процесс без памяти**. Он не знает ничего о предыдущих запросах.

Поэтому при доработке приложение **пересобирает полный контекст** и отправляет его целиком:

```
Ты — помощник по обработке текста. Верни ТОЛЬКО готовый текст
без пояснений, без комментариев и без markdown-разметки.

Исходная задача: <промпт выбранного действия>

=== ИСХОДНЫЙ ТЕКСТ ===
<текст пользователя>
=== КОНЕЦ ===

=== ПРЕДЫДУЩИЙ РЕЗУЛЬТАТ ===
<последний ответ Claude>
=== КОНЕЦ ===

Доработай предыдущий результат с учётом замечания: <уточнение пользователя>
```

Приложение хранит в памяти: исходный текст, выбранное действие, последний результат. Этого достаточно для любого количества итераций доработки.

Альтернативный путь — вести сессию через `claude -p --output-format json` и `--resume <session_id>` — сознательно **не используем**: он экономнее по токенам, но привязывает нас к состоянию на стороне CLI и хуже отлаживается.

## 5. Структура файлов

```
Редактор текста на CC/
├── texthelper.py          # точка входа: иконка в трее, меню, вызов Claude
├── ui.py                  # окна: действия, результат «БЫЛО → СТАЛО», сообщения
├── speech.py              # запись с микрофона и распознавание речи
├── create_shortcut.py     # создание ярлыка на рабочем столе (запускается один раз)
├── install_speech.py      # разовая загрузка модели распознавания речи
├── settings.default.json  # действия по умолчанию (эталон)
├── requirements.txt       # зависимости
└── README.md              # установка и запуск
```

Рабочие данные лежат отдельно от кода:

```
%LOCALAPPDATA%\TextHelper\
├── settings.json     # настройки пользователя
├── texthelper.log    # лог работы
├── icon-<отпечаток>.ico   # значок для ярлыка
├── clip.png          # последняя картинка из буфера обмена
└── speech-model\     # модель распознавания речи (~25 МБ)
```

При первом запуске `settings.json` создаётся копированием из `settings.default.json`.

## 6. Формат настроек

Файл `settings.json`. Пункт меню «⚙️ Настройки» открывает его в «Блокноте»; после сохранения настройки перечитываются без перезапуска приложения.

```json
{
  "model": "sonnet",
  "timeout_seconds": 60,
  "max_input_chars": 10000,
  "actions": [
    {
      "title": "✏️ Проверь орфографию",
      "prompt": "Исправь орфографические и пунктуационные ошибки. Сохрани стиль и структуру текста, ничего не переписывай по смыслу."
    },
    {
      "title": "🌍 Переведи на английский",
      "prompt": "Переведи текст на английский язык, сохраняя тон и стиль оригинала.",
      "images": true
    },
    {
      "title": "🎩 Сделай формальнее",
      "prompt": "Перепиши текст в официально-деловом стиле. Сохрани все факты и смысл."
    },
    {
      "title": "🔄 Упрости текст",
      "prompt": "Упрости текст: короткие предложения, простые слова, без канцелярита. Смысл сохрани полностью."
    }
  ]
}
```

Поле `"images": true` разрешает действию работать с картинками из буфера обмена; без него действие принимает только текст.

Пользователь может добавлять, удалять и переписывать действия — код при этом не трогается. Меню строится из массива `actions` динамически.

Если файл настроек испорчен (невалидный JSON), приложение не падает: показывает окно с описанием ошибки и работает на настройках по умолчанию.

## 7. Интерфейс

### Иконка в трее

- **Профессор** — растрёпанная белая шевелюра и высунутый язык на фиолетовом фоне: обычное состояние, готов к работе
- **⏳** — песочные часы на оранжевом: идёт обработка запроса

Значок рисуется кодом в размере 256 пикселей и уменьшается до 64 — так края получаются гладкими. Отдельной картинки в проекте нет.

Файл `.ico` для ярлыка сохраняется в `%LOCALAPPDATA%\TextHelper\` под именем с отпечатком картинки — `icon-<отпечаток>.ico`. Это не украшательство: Windows запоминает значки по пути к файлу и при изменении содержимого продолжает показывать старую картинку из кэша. Меняется рисунок — меняется имя файла, и подмены не происходит.

Меню открывается **левым кликом** по иконке (на Windows это не поведение по умолчанию, нужно задать явно).

### Оформление

Единая синяя палитра во всех окнах: фон, поверхности чуть светлее и темнее его, весь текст белый, подписи — бледно-голубые. Белого фона нет нигде.

Кнопки действий нарисованы на холсте со скруглёнными углами: обычная кнопка Windows углы скруглять не умеет.

Единственная белая кнопка в интерфейсе — «Отправить» в окне результата. Это сознательно: в окне должно быть ровно одно место, которое явно зовёт нажать.

Все цвета собраны в одном блоке в начале `ui.py` и читаются в момент создания окна, а не при загрузке модуля. Поэтому сменить палитру целиком — правка десяти строк, а не поиск цветов по всему файлу.

### Панель действий

Компактная панель появляется сразу после запуска и **висит поверх всех окон** в правом верхнем углу экрана: подпись «Выделите текст — и жмите» и кнопки по числу действий из настроек. Та же панель открывается пунктом «✦ Меню действий» в меню трея.

Панель, а не обычное окно, — потому что пользователь работает в Word или браузере, и помощник должен быть под рукой всё время, не требуя переключений и не закрывая середину документа. Обычное окно уходило за документ при первом же клике в него.

Панель заодно решает вторую задачу: Windows прячет новые значки трея в скрытую область под стрелкой `^`, и найти иконку с первого раза удаётся не всем. С панелью приложение работоспособно независимо от этого.

Внизу панели — «Настройки» и «Выход». Они дублируют пункты меню трея, потому что до самого трея дотянуться получается не всегда: Windows прячет новые значки, и полагаться только на них нельзя.

Закрытие панели не выключает приложение: оно остаётся в трее, вернуть панель можно из меню или повторным кликом по ярлыку.

### Работа с картинками

Переводить можно не только выделенный текст, но и картинку: снимок экрана, фотографию документа, скриншот письма.

Пользователь нажимает `Win + Shift + S`, выделяет кусок экрана — снимок попадает в буфер обмена — и жмёт кнопку перевода на панели. Так же работает копирование файла с картинкой в проводнике.

Как это устроено:

1. Приложение смотрит, что лежит в буфере обмена: текст или картинка.
2. Картинка сохраняется в файл `%LOCALAPPDATA%\TextHelper\clip.png`.
3. Claude получает задание прочитать этот файл и выполнить с найденным текстом действие. Для этого ему разрешается ровно один инструмент — чтение файла (`--allowed-tools Read --permission-mode acceptEdits`), а рабочей папкой становится папка с картинкой. Для обычного текста инструменты по-прежнему отключены полностью.
4. В поле «БЫЛО» показывается пометка, что исходник — картинка, и её размер. Текста там нет: он существует только на изображении.
5. Доработка работает и здесь — путь к картинке передаётся в каждом запросе, поэтому на «сделай короче» Claude при необходимости перечитает исходник.

Ответ приходит дольше обычного: 12–13 секунд против 7, изображение нужно рассмотреть. Расход лимитов подписки на картинку тоже заметно выше.

**Какие действия работают с картинками, задаётся в настройках** — полем `"images": true` у действия. Сейчас оно стоит у двух переводов. Остальные действия к картинкам не применяются осознанно: исправленную орфографию некуда вернуть, текст на изображении не заменишь.

Важное следствие для чтения буфера: **очищать буфер обмена нельзя**. Раньше приложение очищало его, чтобы отличить новое выделение от старого содержимого. Со снимком экрана это означало бы, что картинка пропадёт до того, как её успеют прочитать. Поэтому новое выделение определяется иначе — по тому, что содержимое буфера изменилось после `Ctrl+C`.

### Как берётся текст

Приложение **само копирует выделенное**: возвращает фокус окну, с которым работал пользователь, посылает туда `Ctrl+C` и читает буфер обмена. Окно запоминается заранее — приложение периодически отмечает, какое чужое окно было активным.

Порядок такой:
1. Есть выделение — работаем с ним.
2. Выделения нет, а в буфере лежит картинка и действие умеет с ними работать — работаем с картинкой.
3. Выделения нет, но в буфере есть текст — работаем с ним (пользователь мог скопировать заранее).
4. Пусто везде — подсказка на панели «Выделите текст или скопируйте картинку».

Содержимое буфера обмена не портится: оно не очищается ни на каком шаге.

Требование «сначала нажмите `Ctrl+C`» из исходной схемы сознательно снято: пользователь выделяет текст и жмёт кнопку, лишний шаг не нужен. Без этого приложение молча обрабатывало старое содержимое буфера — самая неприятная из возможных ошибок, потому что выглядит как правильная работа.

### Окно результата

- Заголовок — название выбранного действия, чтобы было видно, что именно делали.
- Поле «БЫЛО» — исходный текст, только для чтения, фон темнее основного.
- Поле «СТАЛО» — результат, фон светлее и светлая рамка, текст можно выделить и скопировать вручную.
- Поле уточнения с подсказкой «сделай ещё короче» + кнопка «Отправить».
- Кнопка «📋 Скопировать» — кладёт результат в буфер обмена и на пару секунд меняет надпись на «✓ Скопировано».
- Окно закрывается по `Esc` или крестику.
- Окно появляется по центру экрана и **остаётся поверх остальных окон**, пока его не закроют. Иначе оно уходит за документ при первом же клике в него, и результат остаётся незамеченным.
- Во время доработки поля блокируются, показывается «⏳ Обрабатываю…».

### Голосовой ввод уточнений

Рядом с полем уточнения — кнопка «Голос». Первое нажатие начинает запись (кнопка меняется на «Стоп», в строке состояния — «Говорите…»), второе останавливает и через пару секунд вписывает распознанный текст в поле.

Распознавание идёт **на компьютере пользователя**: модель Zipformer2 от авторов Vosk (ошибка распознавания 9.8% на Common Voice ru), формат ONNX, движок sherpa-onnx. Интернет не нужен, речь никуда не отправляется, права администратора не требуются.

Модель скачивается один раз командой `python install_speech.py` — около 25 МБ в `%LOCALAPPDATA%\TextHelper\speech-model`. При запуске приложения модель прогревается в фоне, чтобы первое нажатие «Голос» не ждало загрузки.

**Почему не встроенный в Windows `Win + H`.** Сначала ставка была на него: бесплатно и без кода. На практике не сработало по двум причинам сразу. Во-первых, на машине не установлено ни одного речевого движка, а онлайн-распознавание выключено в настройках приватности — то есть `Win + H` без ручной настройки Windows нерабочий. Во-вторых, и это важнее, он вставляет распознанное через механизм, который окна на tkinter не поддерживают: Windows не считает их текстовыми полями, и текст уходит в пустоту. Своя кнопка снимает обе проблемы — приложение само кладёт текст в поле.

**Почему sherpa-onnx, а не vosk.** Изначально планировался vosk. Его официальный сайт из сети пользователя недоступен: соединение открывается, но загрузка стоит — 30 КБ за десять минут. Hugging Face доступен и работает быстро, а там та же модель выложена в формате ONNX. Движок другой, модель и качество распознавания те же.

**Буфер обмена автоматически не перезаписывается.** Результат попадает в буфер только по кнопке «Скопировать» — иначе исходный текст пользователя молча потеряется.

## 8. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Нет ни выделения, ни текста в буфере | Подсказка на панели: «Выделите текст в документе» |
| Текст длиннее `max_input_chars` | Окно с предупреждением и предложением обработать первые N символов |
| `claude.exe` не найден | Окно: «Claude Code не найден. Установите его и выполните вход» + путь, где искали |
| Вход в аккаунт не выполнен | Окно с подсказкой выполнить `claude login` в терминале |
| Таймаут | Окно: «Claude не ответил за 60 секунд». Иконка возвращается в ✦ |
| Ненулевой код выхода | Окно с текстом ошибки из stderr, полная версия — в логе |
| Лимиты подписки исчерпаны | Показываем сообщение Claude как есть, без интерпретации |

Общее правило: **приложение никогда не падает молча**. Любая ошибка — это либо окно, либо запись в лог, а иконка всегда возвращается в рабочее состояние.

### Логирование

Файл `%LOCALAPPDATA%\TextHelper\texthelper.log`: время, выбранное действие, длина текста, время ответа, код выхода, текст ошибки. Сам текст пользователя в лог не пишется.

## 9. Учтённые баги из демонстрации преподавателя

**Баг 1 — при доработке терялся исходный текст.** В демонстрации на запрос «сделай ещё короче» Claude ответил: «Не хватает исходного текста, который нужно доработать — пришлите его». Причина: приложение отправляло только само уточнение, без исходного текста и предыдущего результата, а процесс `claude -p` не помнит предыдущих запросов.

*Решение:* приложение хранит контекст диалога у себя и пересобирает полный промпт при каждом вызове (см. раздел 4). Проверяется отдельным пунктом приёмки.

**Баг 2 — не работали системные уведомления.** В демонстрации уведомления вне собранного приложения не показывались, пришлось делать обходной путь. На Windows та же проблема по другой причине: toast-уведомления требуют зарегистрированной идентичности приложения, иначе молча не появляются.

*Решение:* уведомления вообще не используются как способ сообщить о результате. Всё показывается в окне и через смену иконки в трее. Никакой информации пользователь не теряет.

**Баг 3 — ответ Claude в разговорном стиле.** Без жёсткой инструкции модель добавляет вводные фразы, и они попадают в поле «СТАЛО».

*Решение:* строгая преамбула «верни ТОЛЬКО готовый текст» в каждом промпте + обрезка обрамляющих markdown-кавычек в ответе.

## 10. Запуск с рабочего стола

Приложение запускается вручную, вместе с Windows не стартует.

На рабочем столе лежит ярлык **TextHelper** с иконкой приложения. Двойной клик — приложение запускается и сразу показывает окно со списком действий.

Ярлык создаётся один раз командой `python create_shortcut.py`. Скрипт делает две вещи: сохраняет иконку в формате `.ico` (ярлыку нужен именно он) и создаёт сам ярлык через стандартный механизм Windows. Запуск идёт через `pythonw.exe`, а не `python.exe`, — иначе рядом с приложением висело бы чёрное окно консоли.

## 11. Этапы работы

1. Каркас: иконка в трее, меню из четырёх пунктов, выход из приложения.
2. Чтение буфера обмена и вызов `claude -p` — результат пока в консоль.
3. Окно «БЫЛО → СТАЛО» с кнопкой «Скопировать».
4. Доработка с полным контекстом (закрывает баг 1).
5. Вынос действий в `settings.json`, пункт «Настройки».
6. Обработка ошибок, смена иконки на ⏳, логирование.
7. Панель действий и ярлык на рабочем столе.
8. Голосовой ввод уточнений.
9. Тестирование по чек-листу, `README.md`.

## 12. Критерии готовности

- [ ] Двойной клик по ярлыку на рабочем столе запускает приложение
- [ ] Сразу после запуска открывается панель действий в правом верхнем углу
- [ ] Панель остаётся видна поверх Word и браузера, повторный клик по ярлыку не плодит копии приложения
- [ ] **Выделенный в Word текст обрабатывается без нажатия `Ctrl+C`**
- [ ] Снимок экрана из `Win + Shift + S` переводится обеими кнопками перевода
- [ ] Доработка перевода с картинки сохраняет контекст
- [ ] Иконка ✦ появляется в трее, клик по ней открывает меню из действий, заданных в `settings.json`
- [ ] Во время работы иконка — ⏳, окно результата не уходит за документ
- [ ] Окно показывает «БЫЛО» и «СТАЛО», кириллица отображается корректно
- [ ] Кнопка «Скопировать» кладёт результат в буфер обмена
- [ ] **Доработка работает: «сделай короче» после первого результата возвращает сокращённый текст, а не просьбу прислать исходник**
- [ ] Подряд три итерации доработки не теряют контекст
- [ ] Отсутствие выделения и пустой буфер дают понятную подсказку, а не падение
- [ ] Добавленное вручную в JSON пятое действие появляется на панели и в меню трея
- [ ] Кнопки «Настройки» и «Выход» на панели работают
- [ ] Кнопка «Голос» записывает речь, распознанный текст попадает в поле уточнения и обрабатывается так же, как набранный с клавиатуры
- [ ] Ни при одном сценарии на экране не мигает окно консоли
- [ ] Выход из приложения убирает иконку из трея

## 13. Что сознательно не делаем

- Глобальные горячие клавиши — только иконка в трее и окно действий.
- Автозапуск вместе с Windows — приложение запускается вручную, с ярлыка на рабочем столе.
- Сборку в `.exe` — задание запускается одной командой.
- Историю обработанных текстов — окно закрыли, контекст забыли.
- Графический редактор действий — правка JSON в «Блокноте» достаточна и нагляднее.
